# 마크다운 수퍼 포맷 (Markdown Super Format)

> **기준:** MultiMarkdown 6(MMD)을 기본으로 한다. MMD가 지원하지 않는 문법은 **Pandoc Markdown → markdown-it → Obsidian** 순으로 가져온다.
> 같은 기능이 여러 곳에 있으면 앞 순서의 문법을 쓴다.
>
> **출처 표기:** 출처 열에는 해당 문법을 지원하는 **모든** 표준을 적는다. `(플러그인)`은 markdown-it에서 확장 플러그인으로만 지원함을 뜻한다.
> 약어: CM = CommonMark, GFM = GitHub Flavored Markdown, MMD = MultiMarkdown 6, PD = Pandoc Markdown, MI = markdown-it, OB = Obsidian

[TOC depth=2]

## 0. 설계 원칙

1. **MMD 우선**: MMD 문법으로 표현 가능하면 MMD 문법만 쓴다.
2. **출처 순서**: MMD → Pandoc → markdown-it(GFM 계열) → Obsidian.
3. **충돌 금지**: 같은 기호가 두 의미를 갖지 않도록 아래 "충돌 해결" 규칙을 따른다.
4. **렌더링 안전성**: 가져온 문법은 해당 도구가 없어도 읽기 쉬운 원문이 남도록 쓴다.
5. **입력 편의성**: 기호 한 글자로 동작을 바꾸지 않는다. 실행·렌더링 여부는 키워드(`run`, `render`)로 명시한다.

## 충돌 해결 규칙

| 충돌                                               | 해결                                                                          |
| -------------------------------------------------- | ----------------------------------------------------------------------------- |
| `^a^`(MMD 위첨자) vs `^id`(Obsidian 블록 참조)     | 블록 참조는 **줄 끝**에만 쓴다. 위첨자는 문장 중간에 쓴다.                    |
| `~a~`(아래첨자) vs `~~a~~`(취소선)                 | `~~`는 취소선, `~`는 아래첨자로 구분한다. 취소선 안에 아래첨자를 쓰지 않는다. |
| `#태그`(Obsidian) vs `# 제목`(MMD)                 | 태그는 `#` 뒤에 공백이 없고 행 시작이 아니어야 한다.                          |
| `[#id]`(MMD 제목 ID) vs `[#label]`(MMD 상호 참조)  | 제목 끝의 `[#id]`는 ID, 본문 속 `[#label]`은 참조다.                          |
| `{...}`(Pandoc 속성) vs `{width=...}`              | 이미지·div 속성은 Pandoc 형식을 쓰고, 제목 ID는 MMD `[#id]`를 쓴다.           |
| `[[...]]`(Obsidian 위키링크) vs `[...]`(일반 링크) | `[[`는 위키링크, `[`는 일반 링크다.                                           |
| `%%`(Obsidian 주석) vs `%`(LaTeX)                  | `$...$` 수식 안에서는 `%%`를 주석으로 해석하지 않는다.                        |

## 주의

- 이 문서는 **설계안**이다. 실제 렌더러마다 동작이 다르므로, 출력 도구에 맞춰 일부 문법을 바꿔야 할 수 있다.
- Pandoc YAML과 MMD 메타데이터는 동시에 쓰지 않는다.
- 공식 명세와 다른 부분이 있을 수 있으니 최종 사용 전 각 도구에서 샘플로 검증한다.

## 11. 포맷별 지원 표준 문법

각 포맷이 기본으로 지원하는 문법과, 확장 플러그인으로만 지원하는 문법, 지원하지 않는 문법을 정리한다. 비교표(1~10장)의 결과를 포맷별로 다시 묶은 것이다.

| 포맷 | 기준 | 기본 지원 | 플러그인/확장으로 지원 | 미지원 |

**참고**

- 표준 CommonMark가 정의하는 범위는 기본 문법(제목, 강조, 목록, 코드, 인용, 링크, 이미지, HTML, 이스케이프)에 한정된다. 나머지는 GFM 또는 각 포맷 확장이다.
- 플러그인 항목은 해당 플러그인을 설치했을 때만 동작한다.
- 이 표는 1~10장 비교표를 근거로 정리했으며, 버전에 따라 지원 범위가 달라질 수 있다.

## 12. SuperMarkdown 표 확장 (셀 병합)

구분선 `|---|---|---|` 위의 행은 **헤더**, 아래 행은 **컨텐츠 셀**이다. 셀 내용이 아래 마커 중 하나뿐이면 병합 지시로 해석한다. 헤더와 컨텐츠 셀은 각각 1개 이상의 행을 가질 수 있다.

| 마커 | 의미           | 병합 대상      |
| ---- | -------------- | -------------- |
| `^`  | 위 셀과 병합   | 바로 위 셀     |
| `<`  | 좌측 셀과 병합 | 바로 왼쪽 셀   |
| `>`  | 우측 셀과 병합 | 바로 오른쪽 셀 |

### 병합 규칙

| 규칙                     | 내용                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 헤더 내 병합             | 헤더 행 안에서 `<`, `>`, `^`로 병합할 수 있다.                                                             |
| 컨텐츠 내 병합           | 컨텐츠 행 안에서 `<`, `>`, `^`로 병합할 수 있다.                                                           |
| 헤더·컨텐츠 간 병합 금지 | 구분선을 사이에 둔 셀끼리는 병합할 수 없다. 첫 번째 컨텐츠 행의 `^`는 헤더 셀을 가리킬 수 없으므로 오류다. |
| 연속 병합                | 같은 방향 마커가 연속되면 병합 영역이 확장된다. 예: 세로 3칸 병합은 `^`를 두 행 연속 쓴다.                 |
| 병합 셀 내용             | 병합 영역의 내용은 시작 셀(가장 위·가장 왼쪽)의 내용을 쓴다.                                               |
| 이스케이프               | 마커 문자 자체를 쓰려면 `\^`, `\<`, `\>`로 쓴다.                                                           |

### 예시

```markdown
| 구분 | 측정 | < |
| ^ | 1 회 | 2회 |
|---|---|---|
| 속도 | 1회차 | 10 |
| ^ | 2회차 | 12 |
```

| 구분 | 측정 | < |
| ^ | 1 회 | 2회 |
|---|---|---|
| 속도 | 1회차 | 10 |
| ^ | 2회차 | 12 |


```markdown
| 구분 | 측정 | < |
|---|---|---|
| 속도 | 1회차 | 10 |
| ^ | 2회차 | 12 |
```

| 구분 | 측정 | < |
|---|---|---|
| 속도 | 1회차 | 10 |
| ^ | 2회차 | 12 |


- 헤더 `측정`은 2개 열(측정, 결과)에 걸친다. 3번째 열의 `<`가 좌측 `측정`과 병합한다.
- 첫 번째 열 `속도`는 두 행에 걸친다. 2행의 `^`가 위 `속도`와 병합한다.

### 충돌 해결

| 충돌                                | 해결                                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------------------------- |
| 셀 내용 `^`, `<`, `>` (실제 텍스트) | 셀 전체가 마커 한 글자일 때만 병합으로 해석한다. 텍스트로 쓰려면 `\^`처럼 이스케이프한다. |
| MMD 위첨자 `x^2^`                   | 셀 내용 전체가 `^` 한 글자인 경우에만 병합 마커다. 문장 속 위첨자와 충돌하지 않는다.      |
| 인용문 `>`                          | 인용문은 행 시작 `>`이고 표 행은 `\|`로 시작하므로 충돌하지 않는다.                       |
| 기존 표준 렌더러                    | 표준 렌더러는 마커를 글자 그대로 출력한다. SuperMarkdown 렌더러에서만 병합이 적용된다.    |

## 13. 코드 실행 결과 (실행 청크)

실행 여부는 **`run` 키워드**로만 정한다. 점(`.`)이나 기호 한 글자로 동작을 바꾸지 않는다. 실행 결과는 기본적으로 파일에 저장하지 않고 렌더링 시 생성한다.

### 13.1 문법 구분

| 구분      | 문법                | 동작                                       |
| --------- | ------------------- | ------------------------------------------ |
| 정적 코드 | ` ```python `       | 하이라이트만 한다. 실행하지 않는다.        |
| 실행 청크 | ` ```{python run} ` | 코드를 실행하고 결과를 표시한다.           |
| raw 블록  | ` ```{=latex} `     | 특정 출력 형식에만 그대로 넣는다. (Pandoc) |

- 정적 코드와 실행 청크는 언어 이름이 같아도 `{}`와 `run` 키워드로 구분한다.
- `run`을 빠뜨리면 정적 코드가 되므로 실행되지 않는다. 실행을 원할 때만 `run`을 쓴다.

### 13.2 정보 문자열과 청크 옵션

캡션과 라벨은 펜스 **정보 문자열**에 쓴다(15장). 실행 동작은 청크 첫 줄 아래 `#|` 줄에 `키: 값`으로 쓴다.

| 위치        | 옵션      | 기본값  | 의미                                     |
| ----------- | --------- | ------- | ---------------------------------------- |
| 정보 문자열 | `caption` | 없음    | 캡션                                     |
| 정보 문자열 | `label`   | 없음    | 라벨. `[#lst:name]` 등 상호 참조에 쓴다. |
| `#\|`       | `echo`    | `true`  | 코드 표시 여부                           |
| `#\|`       | `output`  | `true`  | 결과 표시 여부                           |
| `#\|`       | `cache`   | `false` | 결과를 저장해 재사용할지 여부            |
| `#\|`       | `error`   | `false` | 오류가 나도 실행을 계속할지 여부         |

````markdown
```{python run label=calc caption=계산 예시}
#| echo: true
#| output: true
#| cache: false
print(1 + 2)
```
````

### 13.3 결과 렌더링

- 결과는 청크 바로 아래에 렌더링 결과로 표시한다. 파일 본문에는 결과를 쓰지 않는다.
- `output: false`이면 결과를 숨기고, `echo: false`이면 코드를 숨긴다. 둘 다 `false`이면 청크는 실행만 한다.
- `cache: true`일 때만 결과를 저장한다. 저장 위치와 형식은 13.5에서 정한다.

### 13.4 실행 허용

- 문서 메타데이터에 `execute: true`가 있을 때만 실행 청크를 실행한다.
- 값이 없거나 `false`이면 실행 청크는 코드만 표시하고 실행하지 않는다.

```markdown
---
execute: true
---
```

### 13.5 캐시 결과 저장

- `cache: true` 청크의 결과는 문서와 같은 폴더의 `.cache/` 아래에 청크 `label`을 파일명으로 저장한다.
- 코드가 바뀌면 캐시를 무효화하고 다시 실행한다.
- 캐시 파일은 버전 관리에서 제외하는 것을 권장한다.

### 13.6 충돌 해결

| 충돌                                                | 해결                                                            |
| --------------------------------------------------- | --------------------------------------------------------------- |
| `{python run}` 실행 청크 vs ` ```python ` 정적 코드 | `run` 키워드로만 구분한다. 점 표기는 쓰지 않는다.               |
| `#\|` 옵션 줄 vs 일반 코드 주석                     | 청크 첫 줄 바로 아래 연속된 `#\|` 줄만 옵션으로 해석한다.       |
| `label` vs 상호 참조 `[#label]`                     | 정의는 정보 문자열 `label=`에, 참조는 본문의 `[#label]`에 쓴다. |
| 실행 허용 vs 보안                                   | `execute` 값이 없으면 실행하지 않는다.                          |

## 14. 다이어그램 렌더링 청크

PlantUML, Mermaid 등 텍스트로 그림을 만드는 언어는 실행 청크와 같은 방식으로 기술하되, 결과가 값이 아니라 **이미지**라는 점이 다르다. 렌더링 여부는 `render` 키워드로 정한다.

### 14.1 문법 구분

| 구분        | 문법                                              | 동작                                                            |
| ----------- | ------------------------------------------------- | --------------------------------------------------------------- |
| 정적 코드   | ` ```plantuml `, ` ```mermaid `                   | 이미지로 변환해 본문에 표시한다. 기존 호환성을 위해 렌더링한다. |
| raw 블록    | ` ```{=plantuml} `, ` ```{=mermaid} `             | 텍스트로만 표시한다.                                            |
| 렌더링 청크 | ` ```{plantuml render} `, ` ```{mermaid render} ` | 이미지로 변환해 본문에 표시한다.                                |

`render` 키워드는 13장의 `run`과 같은 규칙이다.

### 14.2 정보 문자열과 청크 옵션

| 위치        | 옵션      | 기본값  | 의미                                           |
| ----------- | --------- | ------- | ---------------------------------------------- |
| 정보 문자열 | `caption` | 없음    | 그림 캡션                                      |
| 정보 문자열 | `label`   | 없음    | 그림 라벨. `[#fig:name]` 상호 참조에 쓴다.     |
| `#\|`       | `format`  | `svg`   | 출력 형식(`svg`, `png`)                        |
| `#\|`       | `width`   | 없음    | 그림 너비(예: `60%`)                           |
| `#\|`       | `echo`    | `false` | 코드 블록을 그림과 함께 표시할지 여부          |
| `#\|`       | `output`  | `true`  | 그림 표시 여부. `false`이면 렌더링하지 않는다. |
| `#\|`       | `cache`   | `false` | 렌더링 결과를 저장해 재사용할지 여부           |

### 14.3 코드와 그림 표시

| 목적                      | 방법                          | 결과                              |
| ------------------------- | ----------------------------- | --------------------------------- |
| 그림만                    | `echo: false` (기본)          | 이미지만 표시                     |
| 코드와 그림 모두          | `echo: true`                  | 코드 블록 다음에 이미지 표시      |
| 코드만 (그림 생략)        | `echo: true`, `output: false` | 코드 블록만 표시, 렌더링하지 않음 |
| 코드 예시만 (렌더링 없음) | ` ```plantuml ` 정적 블록     | 텍스트로만 표시                   |

````markdown
```{plantuml render caption="로그인 흐름" label=fig:flow}
#| echo: true
#| format: svg
@startuml
Alice -> Bob: 요청
Bob --> Alice: 응답
@enduml
```
````

### 14.4 실행 허용과 캐시

- 외부 렌더러(Java, Kroki 등)를 호출하므로 문서 메타데이터 `execute: true`가 있을 때만 렌더링한다. 없으면 정적 코드로 표시한다.
- `cache: true`이면 렌더링 이미지를 `.cache/` 아래에 `label` 파일명으로 저장한다. 13.5의 규칙과 같다.

### 14.5 환경별 동작

- GitHub와 Obsidian은 ` ```mermaid `를 기본 렌더링하므로, 해당 환경에서는 정적 블록만으로도 그림이 보인다.
- 렌더링 청크 `{plantuml render}`, `{mermaid render}`는 SuperMarkdown 렌더러에서만 동작한다. 다른 렌더러에서는 정적 코드로 표시된다.

### 14.6 충돌 해결

| 충돌                     | 해결                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 렌더링 청크 vs 정적 코드 | `render` 키워드로만 구분한다.                                                                                             |
| `echo` 기본값 차이       | 실행 청크(13장)는 `echo: true`, 다이어그램 청크(14장)는 `echo: false`가 기본이다. 그림이 본체이므로 코드는 기본 숨김이다. |
| 그림 캡션과 표 캡션      | 그림은 정보 문자열 `caption`, 표는 `[Table: 캡션]`을 쓴다.                                                                |

## 15. 코드 블록 캡션과 라벨

캡션과 라벨은 **펜스 정보 문자열**에만 쓴다. `#|` 옵션으로는 쓰지 않는다. 13장·14장 청크에도 같은 규칙을 적용한다.

### 15.1 문법

````markdown
```python caption="예시 코드" label=lst:hello
print("hello")
```
````

| 구분        | 문법                                                          | 비고                           |
| ----------- | ------------------------------------------------------------- | ------------------------------ |
| 정적 코드   | ` ```python caption=예시 label=lst:hello `                    | 값에 공백이 없으면 따옴표 생략 |
| 실행 청크   | ` ```{python run caption=예시 label=lst:hello} `              | 13장과 같은 속성               |
| 렌더링 청크 | ` ```{plantuml render caption="로그인 흐름" label=fig:flow} ` | 14장과 같은 속성               |

### 15.2 규칙

- 값에 공백이 있으면 따옴표로 감싼다. 공백이 없으면 따옴표를 생략한다.
- 캡션은 코드 블록 위에 표시한다.
- `label`은 접두사로 종류를 구분한다: `lst:`(코드), `fig:`(그림). 상호 참조는 `[#lst:name]`, `[#fig:name]`으로 한다.
- 캡션과 라벨이 없으면 캡션 영역을 만들지 않는다.

### 15.3 충돌 해결

| 충돌                                 | 해결                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------- |
| 정보 문자열 `caption` vs `#\|` 옵션  | 캡션·라벨은 정보 문자열에만 쓴다. `#\| caption:` 옵션은 정의하지 않는다.  |
| 정보 문자열 `key=value` vs 언어 이름 | 언어 이름 뒤 공백 다음의 `key=value`만 속성으로 본다.                     |
| 코드 캡션 vs 그림 캡션               | 둘 다 `caption`을 쓴다. 종류는 `label` 접두사(`lst:`, `fig:`)로 구분한다. |

## 16. 펜스 div (구획 블록)

콜아웃, 조건부 블록, 탭 등을 하나의 구조로 묶는 Pandoc 방식의 펜스 div다. 속성은 모두 선택 사항이다.

### 16.1 문법

```markdown
:::{.warning title=주의}
내용은 일반 마크다운으로 쓴다.
:::
```

| 요소             | 의미                                                    |
| ---------------- | ------------------------------------------------------- |
| `:::` (3개 이상) | 구획 시작과 끝. 닫는 `:::`는 같은 개수 이상이어야 한다. |
| `.class`         | 선택. 클래스. 스타일과 조건부 출력에 쓴다.              |
| `#id`            | 선택. 식별자. 상호 참조가 필요할 때만 쓴다.             |
| `key=value`      | 선택. 예: `title`. 값에 공백이 있으면 따옴표로 감싼다.  |

### 16.2 중첩

바깥 구획은 더 많은 콜론을 쓴다. 중첩은 콜론 개수로만 구분한다.

```markdown
::::{.tabset}
:::{.tab title=Python}
내용
:::
::::
```

### 16.3 충돌 해결

| 충돌                  | 해결                                                    |
| --------------------- | ------------------------------------------------------- |
| `:::`와 본문 콜론     | 줄 시작에 `:::`만 단독으로 있을 때만 구획으로 해석한다. |
| 펜스 div vs 코드 블록 | 코드 블록 안의 `:::`는 구획으로 해석하지 않는다.        |

## 17. 콜아웃 (Obsidian 문법으로 통일)

콜아웃은 Obsidian 문법만 쓴다. 펜스 admonition은 쓰지 않는다.

### 17.1 문법

```markdown
> [!NOTE] 제목
> 내용은 일반 마크다운으로 쓴다.
```

| 요소         | 의미                                                         |
| ------------ | ------------------------------------------------------------ |
| `> [!종류]`  | 콜아웃 시작. 종류는 대괄호 안에 쓴다.                        |
| `제목`       | 같은 줄의 나머지 텍스트. 생략하면 종류 이름을 제목으로 쓴다. |
| `> ` 이후 줄 | 콜아웃 본문. 인용문과 같이 `>`로 시작한다.                   |

### 17.2 종류

`note`, `tip`, `warning`, `important`, `caution`, `danger`, `info`, `question`, `quote`, `example`, `abstract`, `success`, `failure`, `bug`, `todo`를 기본으로 쓴다. 종류는 대소문자를 구분하지 않는다.

### 17.3 접기

| 표기              | 동작             |
| ----------------- | ---------------- |
| `> [!NOTE]+ 제목` | 펼친 상태로 시작 |
| `> [!NOTE]- 제목` | 접힌 상태로 시작 |
| `> [!NOTE] 제목`  | 접기 없음        |

### 17.4 중첩

콜아웃 안에 다른 콜아웃을 쓸 수 있다. 인용 깊이를 하나 더 늘린다.

```markdown
> [!NOTE] 바깥
> > [!TIP] 안쪽
> > 내용
```

### 17.5 충돌 해결

| 충돌                                  | 해결                                                                      |
| ------------------------------------- | ------------------------------------------------------------------------- |
| 콜아웃 vs 일반 인용문                 | `[!종류]`가 있을 때만 콜아웃으로 본다. 일반 인용문은 기존대로 `>`만 쓴다. |
| 콜아웃 종류 vs 위키링크 `[[...]]`     | 콜아웃은 `[!`로 시작하므로 위키링크와 구분된다.                           |
| 콜아웃 접기 `+`/`-` vs 수식·목록 기호 | 종류 뒤 `]` 바로 다음에만 접기 기호로 본다.                               |

## 18. 표 셀 체크박스

표 셀 안에서 작업 상태를 표시한다. 상태 문자는 30장의 체크리스트 상태를 그대로 쓴다.

```markdown
| 작업 | 상태 |
|---|---|
| 설계 | [x] |
| 구현 | [ ] |
```

| 규칙             | 내용                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| 허용 형식        | `[ ]`, `[x]`, `[/]`, `[-]` (30장 참조)                                       |
| 렌더링           | 체크박스 기호로 표시한다.                                                    |
| 병합 마커와 충돌 | 병합 마커(12장)는 셀 전체가 `^`, `<`, `>`일 때만 해석하므로 충돌하지 않는다. |

```markdown
[TOC]
```

| 옵션 | 기본값    | 의미                            |
| ---- | --------- | ------------------------------- |
| 깊이 | 제목 1~3  | `[TOC depth=2]`로 변경          |
| 위치 | 문서 상단 | 단독 줄에 써서 위치를 지정한다. |

- `[TOC]`는 단독 줄에만 쓴다. 본문 문장 속 `[TOC]`는 목차로 해석하지 않는다.
- 목차 항목은 제목 ID(1장)를 링크 대상으로 쓴다.

## 20. 수식 번호와 참조

수식 라벨은 블록을 닫는 줄 뒤에 `[#eq:label]`로 쓴다. 정의와 참조 모두 `[#...]` 형식으로 통일한다.

```markdown
$$
E = mc^2
$$ [#eq:energy]

식 [#eq:energy]에 따라 ...
```

| 규칙      | 내용                                                                      |
| --------- | ------------------------------------------------------------------------- |
| 번호 부여 | 수식 블록을 닫는 줄 뒤에 `[#eq:label]`을 붙이면 번호가 자동으로 붙는다.   |
| 참조      | `[#eq:label]`로 번호를 참조한다.                                          |
| 충돌      | 라벨은 `$$` 닫는 줄 뒤에만 쓴다. 수식 내부의 `{}`(LaTeX 그룹)와 구분된다. |

## 21. 상호 참조 자동 번호

제목, 그림, 표, 수식, 코드에 붙인 라벨을 번호로 참조한다. 모든 정의는 `[#종류:이름]` 또는 정보 문자열 `label=종류:이름` 형식이다.

| 참조 대상 | 라벨 정의                         | 참조           | 출력 예 |
| --------- | --------------------------------- | -------------- | ------- |
| 제목      | `## 소개 [#sec:intro]`            | `[#sec:intro]` | 3.2절   |
| 그림      | 14장 정보 문자열 `label=fig:name` | `[#fig:name]`  | 그림 2  |
| 표        | `[Table: 캡션] [#tbl:label]`      | `[#tbl:label]` | 표 1    |
| 수식      | 20장 `$$ ... $$ [#eq:label]`      | `[#eq:label]`  | 식 (3)  |
| 코드      | 15장 정보 문자열 `label=lst:name` | `[#lst:name]`  | 목록 1  |

- 번호는 렌더링 때 계산한다. 파일에 번호를 직접 쓰지 않는다.
- 같은 라벨을 두 번 정의하면 오류다.

## 22. 페이지 나누기

페이지 나누기는 두 가지 형식을 허용한다. 두 형식은 같은 의미다.

```markdown
<!-- pb -->
<!-- pagebreak -->
```

| 출력           | 동작                 |
| ------------- | ------------------- |
| PDF, DOCX     | 페이지 나누기로 변환.    |
| HTML, 미리보기  | 무시                 |

- 정확히 `pb` 또는 `pagebreak`일 때만 페이지 나누기로 동작한다. 그 밖의 주석은 9장의 일반 주석으로 처리한다.
- 기존 raw LaTeX `\newpage`(5장)는 LaTeX 출력 전용으로 유지한다.

## 23. 각주 정의 블록

## 28. 문법 추가 후 충돌 요약

| 추가 문법                           | 충돌 가능 기존 문법 | 해결                                                      |
| ----------------------------------- | ------------------- | --------------------------------------------------------- |
| `:::` 펜스 div                      | 본문 콜론           | 줄 시작 단독 `:::`만 구획으로 본다.                       |
| `[TOC]`                             | 링크 `[TOC]`        | 단독 줄에서만 목차로 본다.                                |
| `$$ ... $$ [#eq:label]`             | 참조 `[#label]`     | 수식 블록 닫는 줄 뒤에서만 라벨로 본다.                   |
| `<!-- pb -->`, `<!-- pagebreak -->` | 일반 주석           | 정확히 `pb` 또는 `pagebreak`일 때만 페이지 나누기로 본다. |
| `{{키}}`                            | LaTeX, 템플릿       | 코드 블록 밖, 메타데이터 키가 있을 때만 치환한다.         |
| `@include 경로`                     | 본문 `@key` 인용    | 줄 시작 `@include `만 포함으로 본다.                      |
| `caption=`, `label=`                | 언어 이름           | 언어 이름 뒤 공백 다음의 `key=value`만 속성으로 본다.     |
| `run`, `render` 키워드              | 언어 이름           | 언어 이름 뒤 공백 다음의 키워드만 실행·렌더링으로 본다.   |

## 29. 키보드 키

키보드 키를 표시한다. 기본 문법은 대괄호 키 표기이고, 대괄호를 쓰기 어려운 환경에서는 `<kbd>`를 쓴다.

### 29.1 문법

| 방식      | 문법                           | 비고                             |
| --------- | ------------------------------ | -------------------------------- |
| 대괄호 키 | `[Ctrl]+[S]`                   | 기본 문법                        |
| HTML 키   | `<kbd>Ctrl</kbd>+<kbd>S</kbd>` | 대괄호 대신 쓸 수 있는 대체 문법 |

```markdown
저장은 [Ctrl]+[S], 취소는 [Esc]를 누른다.
```

저장은 [Ctrl]+[S], 취소는 [Esc]를 누른다.

### 29.2 규칙

| 규칙        | 내용                                                                                                            |
| ----------- | --------------------------------------------------------------------------------------------------------------- |
| 키 이름     | 대괄호 안에 키 이름을 쓴다. 예: `[Ctrl]`, `[Shift]`, `[Enter]`, `[F5]`                                          |
| 조합        | 키 사이는 `+`로 잇는다. 공백은 허용하지만 기본은 붙여 쓴다.                                                     |
| 링크와 구분 | `[Ctrl]` 바로 뒤에 `(url)`이나 `[ref]`가 오면 링크로 본다. 키로 쓰려면 `[Ctrl]` 뒤에 공백이나 다른 문자를 둔다. |
| 코드 블록   | 코드 블록과 인라인 코드 안에서는 키 표기를 해석하지 않는다.                                                     |
| 렌더링      | 키 모양(둥근 상자)으로 표시한다. 지원하지 않는 렌더러에서는 대괄호 텍스트로 남는다.                             |

### 29.3 충돌 해결

| 충돌                                                | 해결                                                    |
| --------------------------------------------------- | ------------------------------------------------------- |
| `[텍스트]` vs 링크 `[텍스트](url)`, `[텍스트][ref]` | 뒤에 `(`나 `[`가 바로 붙으면 링크로 본다.               |
| `[[...]]` 위키링크                                  | 이중 대괄호는 키 표기가 아니라 위키링크다.              |
| 각주 `[^1]`                                         | `^`로 시작하면 각주로 본다.                             |
| 체크박스 `[ ]`, `[x]`                               | 줄 시작 목록 뒤 또는 표 셀 전체일 때만 체크박스로 본다. |

## 30. 체크리스트 상태 확장

작업 목록(3장)과 표 셀 체크박스(18장)의 상태를 표준 두 가지에서 확장한다. 상태 문자는 4종이다.

### 30.1 상태 문자

| 문자  | 의미                | 표시         | 출처          |
| ----- | ------------------- | ------------ | ------------- |
| `[ ]` | 미완료              | 빈 상자      | GFM, Obsidian |
| `[x]` | 완료 (`[X]`도 허용) | 체크         | GFM, Obsidian |
| `[/]` | 진행 중             | 반쯤 찬 상자 | Obsidian 확장 |
| `[-]` | 취소                | 가로선 상자  | Obsidian 확장 |

```markdown
- [ ] 설계 검토
- [/] 구현 중
- [x] 요구사항 정의
- [-] 이전 방식 폐기
```

- [ ] 설계 검토
- [/] 구현 중
- [x] 요구사항 정의
- [-] 이전 방식 폐기

### 30.2 규칙

| 규칙      | 내용                                                                                                                                          |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 대소문자  | `x`와 `X`는 같은 완료 상태다.                                                                                                                 |
| 표준 호환 | `[ ]`와 `[x]`는 GFM·Obsidian에서도 동작한다. `[/]`, `[-]`는 SuperMarkdown 렌더러와 Obsidian 확장에서만 표시되고, 그 밖에서는 원문으로 남는다. |
| 표 셀     | 18장의 표 셀 체크박스도 같은 상태 문자를 쓴다.                                                                                                |
| 집계      | 상태별 개수 집계는 문법에 포함하지 않는다. 필요하면 변수나 도구 기능으로 처리한다.                                                            |

### 30.3 충돌 해결

| 충돌                        | 해결                                                            |
| --------------------------- | --------------------------------------------------------------- |
| `[-]` vs 목록 기호 `-`      | 목록 기호 뒤 공백 다음에 `[-]`가 올 때만 상태로 본다.           |
| `[/]` vs 경로 표기          | 목록 항목 시작에서만 상태로 본다. 본문 중간의 `[/]`는 원문이다. |
| `[x]` vs 콜아웃 `> [!종류]` | 콜아웃은 `>`로 시작하므로 줄 시작 목록 체크박스와 구분된다.     |
